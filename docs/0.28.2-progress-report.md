# AutoVerse 0.28.2 — Progress Report (work in progress)

**Status as of 2026-10-27:** Code changes for all three screens and the Google
Maps launch fix are written and the app **compiles** (`:app:compileDebugKotlin`
passes, including the debug design previews). Unit tests have been updated and
new ones written, but the **test suite, lint, and the debug/release APK builds
have not been run yet**. No Android device or emulator is connected to this
workstation, so **nothing in this report has been verified on the head unit**.

A local safety snapshot of the pre-change code (the uncommitted 0.26–0.28.1
work) was saved as git ref `refs/snapshots/pre-0.28.2` — nothing was pushed,
and the signing key was excluded.

## 1. Root causes found (Phase 0 inspection)

### 1.1 Google Maps "says it's running but doesn't open"

Traced from the tap to the activity launch. Three defects combined:

1. **The Google Maps default was silently lost.**
   `SettingsRepository` read the navigation preference as
   `preferences[KEY_NAVIGATION_PACKAGE]`. For anyone who never explicitly
   picked a navigation app the key is absent, so this returned `null`, which
   overrode the `AppSettings` default (`com.google.android.apps.maps`) and
   meant **"System default"**.
2. **The label and the launch used different providers.**
   The Maps and Apps screens displayed `navigationPageProvider(...)`, which
   promoted "System default" to Google Maps for display — so the screen said
   *"Navigation runs in Google Maps"* / *"Handoff · Google Maps"*. But the
   **Open Google Maps** button called `openNavigationApp()`, which used the
   unpromoted provider ("System default"). System default has no package to
   open, so the launch returned `NOT_SUPPORTED` and **nothing opened**.
3. **Failures were swallowed.** On the Apps screen the outcome of
   `openNavigationApp()` was discarded entirely (`scope.launch { … }`), so the
   tap did nothing visible. Everywhere else, "OPENED" was reported as soon as
   `startActivity` returned, which only means Android accepted a request.

A fourth, smaller issue: the provider list was only discovered after the full
app scan finished, so even a correct Google Maps preference resolved to
"System default" for the first seconds after start.

Not the cause (checked): package visibility — the manifest already declares
`<package android:name="com.google.android.apps.maps" />`.

### 1.2 Home still showed the four old cards

The 0.28.0 60/20/20 cockpit only rendered when the content area right of the
rail was **≥ 880 dp wide** (and Home itself ≥ 840 dp). Otherwise Home fell back
to `PanelGridLayout` — the four cards (Navigation, Now Playing, Favourite Apps,
Driving Status). A 1280×720 head unit at 1.5× density is only ~853 dp wide, so
it **always** received the four-card grid.

### 1.3 Other defects found

- **Rail "Maps" button did nothing** on Home's cockpit layout and on the
  wide Apps layout (`onOpenNavigation = {}`).
- **Apps screen contained a map**: on wide screens it was 70 % Google Maps
  region + 30 % app list.
- **GPS speed could be stale but shown as live**: the cached
  `getLastKnownLocation` (possibly hours old) was fed in as a live reading, and
  if fixes stopped (tunnel) the last speed stayed on screen labelled
  "GPS · live" forever. Updates ran every 500 ms.
- **Location grant didn't start the speedometer** until the next app restart.
- **Call listener kept running in the background** while Home stayed composed.
- **Queue selection reported "sent"** even when the player doesn't advertise
  `ACTION_SKIP_TO_QUEUE_ITEM`.
- **Compact music card (~270 dp) didn't fit** a half-height cockpit panel
  (~190 dp on a 720p unit) — it would clip.
- **Unreachable WebView cockpit** (`Screen.COCKPIT`, `CockpitScreen`,
  `AutoVerseBridge`, `assets/cockpit/`) is still in the APK but never
  navigated to. Left in place this phase (see §4).

## 2. Work done (as asked)

### 2.1 Google Maps launch — fixed at the root (Priority 1)

| Change | File |

### 2.2 Home — four cards removed, cockpit always shown (Priorities 2–3)

- `feature/home/HomeScreen.kt` rewritten. Deleted `PanelGridLayout`,
  `RailSplitLayout`, `CompactScrollLayout`, `MinimalLayout` and every use of
  the Navigation / Favourite Apps / Driving Status cards.
- New pure geometry `core/design/CockpitLayoutPolicy.kt`
  (`cockpitGeometryFor`):
  - **Landscape (SIDE_BY_SIDE):** map 60 % of width; music and speed stacked
    in the remaining 40 % column, each half its height (20 % + 20 %).
  - **Portrait / narrow (STACKED):** map 60 % of height; music and speed side
    by side below.
  - Computed from the real content area (after insets, rail, top bar), never a
    device model. Compact panel mode on short screens.
- **Map region** (`core/design/components/MapsLaunchPanel.kt`, replaces
  `GoogleMapsRegion.kt`): states plainly *"Maps opens full screen — the live
  map isn't shown inside AutoVerse"*; shows Installed / Not installed;
  **Open Google Maps** (disabled when not installed), destination field +
  **Navigate**, live validation, up to 4 recent-destination shortcuts. No
  fake map, no static image, no API-key/billing text.
- **Music panel:** reuses `MediaCard` in a new compact mode — smaller padding
  and spacing; the Now Playing / Queue switch becomes a queue button in the
  artwork row so it fits ~190 dp. Previous / Play-Pause / Next, title, artist,
  artwork, real session queue with skip-to-item.
- **Speed panel** (`SpeedSummaryCard.kt` rewritten): GPS speed in km/h, source
  line (*live / waiting for fix / signal lost / location switched off / no
  location access*), "--" instead of a frozen or zero value, optional one-line
  weather when there's room, **Allow location** action, opt-in **Show incoming
  calls here**. Whole panel opens the Speedometer page.
- **Incoming call:** speed panel is replaced by `IncomingCallCard` (new compact
  mode) while the platform reports RINGING/OFFHOOK; restored when idle. Number
  only when Android supplies it. No answer/reject controls.
- Removed: `FavoriteAppsCard.kt`, `DrivingStatusCard.kt`, `NavigationCard.kt`
  (its `DestinationField` moved to `DestinationField.kt`), Home-panel collapse
  model `HomePanels.kt` + DataStore wiring + "Restore layout" top-bar action.

### 2.3 Apps — 70 % All Apps / 30 % Recently Used, no map (Priority 4)

`feature/apps/AppDrawerScreen.kt` rewritten:

- **All Apps (70 %)**: grid of installed launchable apps with real icons and
  labels, search by name, existing category chips, app count, loading / error /
  empty / no-match states. Favourite stars removed from tiles (favourites had
  no surface left after the Home cards were removed; still editable in
  Settings).
- **Recently Used (30 %)**: AutoVerse's own launch history, newest first,
  deduplicated, bounded (12), resolved against the live catalog so removed apps
  drop out; labelled *"Apps opened from AutoVerse"* (not device-wide; no Usage
  Access requested). **Clear** action; **collapse** gives All Apps the full
  width instantly, a visible chevron restores it; persisted in DataStore
  (`apps_recent_collapsed`).
- Narrow screens: Recently Used becomes a one-row strip above the grid.
- **No map, destination or navigation content anywhere on this screen.**
- Catalog freshness: package broadcasts (existing) + rescan on resume, at most
  once a minute (`MainViewModel.refreshAppsIfStale`).
- Geometry rule: `core/design/DrawerLayoutPolicy.kt` (`appsPanelsSideBySide`).

### 2.4 Maps — 70 % Google Maps / 30 % destinations (Priority 5)

`feature/navigation/NavigationScreen.kt` rewritten:

- 70 % `MapsLaunchPanel`, 30 % **Destinations** panel.
- Saved places: list, tap = navigate in Maps, ✕ = remove; save typed
  destination with optional label. **"Saved …" is shown only after the
  DataStore write succeeded** (`saveSavedPlace` now returns success).
- Recent destinations: recorded only after Android accepted a launch; tap =
  navigate; **Clear** action.
- Collapse: chevron hides the panel, map region takes the width immediately, a
  slim always-visible restore strip remains; persisted
  (`maps_places_collapsed`). Data is never lost on collapse.
- Top bar (clock/connectivity) added for consistency with Home and Apps.
- Geometry rule: `core/design/NavigationLayoutPolicy.kt` (`mapsPanelsSideBySide`).

### 2.5 Navigation rail (Priority 6)

All seven destinations (Home, Apps, Maps, Speed, OBD, Diagnostics, Settings)
are now wired on Home, Apps and Maps — the dead `{}` Maps buttons are fixed.
Existing rail behaviour kept (fixed 76 dp width, icon-only below 392 dp height
so nothing clips, selected state by background + accent).

### 2.6 GPS, calls, media (Priority 7)

- `core/location/SpeedometerManager.kt`: new `GpsStatus` (NO_ACCESS,
  PROVIDER_OFF, WAITING, LIVE, STALE); 5 s staleness timeout via one delayed
  check (no polling); cached last-known fixes used for position only unless
  < 5 s old; 1 s update interval; registers even when GPS is switched off so
  turning it on resumes the readout; pure helpers `speedKmhFromFix`,
  `isFixStale`.
- `AppRoot.kt`: location grant immediately starts the speedometer; call
  listener runs only while Home is shown **and** the activity is started; the
  phone-permission result updates state so listening starts at once.
- `SystemMediaSessionRepository.skipToQueueItem`: returns `NOT_SUPPORTED` when
  the session's action mask lacks skip-to-queue-item
  (`queueSelectionSupported`).

### 2.7 Privacy / local data

  `NavigationPlacesRepository.clearRecents()` (exposed in the UI as **Clear**).
- No new permissions, no new dependencies, no network calls, no API keys.

### 3.3 Google Maps embedding (Priority 8)

- **Not changed this phase.** The on-device probe from 0.28.1 (Diagnostics →
  *Run embedding probe*) is still the evidence collector.
- **Exact result so far: no real-device test has been run**, so no embedding
  approach is proven. The 60 % / 70 % regions therefore remain an honest
  launch surface, and the screen says so.
- Documented platform limits (from 0.28.1 research): adjacent launch works only
  when the user is already in split-screen and the system controls the
  proportions; Activity Embedding needs the embedded app's opt-in (Maps
  doesn't); freeform needs device support; no supported key-free way to keep
  the installed Maps app inside AutoVerse's region. The Maps SDK path needs an
  API key + billing and requires explicit approval.
